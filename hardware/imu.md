# IMU

本机讨论涉及两块 IMU，必须区分数据链路与标定对象。

| 对象 | 数据链路 / 配置约定 | 状态 |
| --- | --- | --- |
| 身体 IMU | IMU-to-servo 板接舵机串口总线，ID 200；按 `imu_to_dxl firmware-1.0.0` 适配 | 驱动基线已选；未留有完整实机运动验收 |
| 头部 IMU | HAT 物理 3/5 脚 I²C，本机 `/dev/i2c-0` | 有扫描和 WHO_AM_I 原始结果，见下文 |

## 头部 I²C 实机记录

此前代码检查记录：2026-11-23 初始检查时 I²C0 没开启，对应排针未配置；后续用户贴出的输出已出现 `/dev/i2c-0`。后一个观测优先，不把旧的“未启用”当作当前状态。

用户实际执行：

```bash
ls -l /dev/i2c-0
sudo i2cdetect -y 0
sudo i2cget -y 0 0x6a 0x0f
```

记录到：

```text
/dev/i2c-0 是字符设备，属组 i2c
总线上应答地址：0x18、0x6a
地址 0x6a 的寄存器 0x0f 返回：0x70
```

这些是原始观测。`0x18` 对应什么器件、`0x6a` 的完整芯片型号和硬件修订，还需要型号资料或更多身份寄存器佐证；不因原版路径默认使用 BMI088，就把所有头部器件写成 BMI088。原项目的部分板型默认头部驱动与这组观测不一定匹配。

“用户要求进一步测试”不等于已经有连续采样、单位、方向和时间戳验证结果。当前记录不能证明头部 IMU 已接入正常运动控制。

## 身体 IMU 的协议基线

- 按用户指示采用复刻项目 `firmware-1.0.0`，不与原 Dynamixel Protocol 2 IMU 布局混用。
- ID 200，与 15 颗舵机 ID 分开。
- 身体姿态用于运动控制与倾倒判定；其传感器到机身的安装四元数保存在飞特标定文件的 `imu_mount`。
- `imu_mount` 使用 `[w,x,y,z]`。不能无证据填单位四元数，也不能拿静态重力推断偏航安装方向。

完整寄存器及诊断机制由[飞特硬件设计](../microduck/docs/design/feetech-hardware.md)维护。

## 标定和预览

- 用户选择身体 IMU **单独按钮标定**，不与舵机零位保存捆绑；实物直立在桌面、静止采样。
- 控制页 3D 预览已在本地代码接入身体 IMU 朝向；头部仍随关节链，不叠加头部 IMU。
- 调零页始终显示固定标准姿态，不随 IMU 倾斜。
- 截至本记录，相关 Studio 修改已本地提交，未据此认定设备的 0.23.2 已包含该预览改动。
